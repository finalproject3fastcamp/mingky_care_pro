# 낮은 장애물 우회 — 참고 스크립트

라이다가 못 보는 낮은 장애물(초음파로만 감지되는 높이)을 만났을 때, 정지하고
좌우를 살펴본 뒤 옆으로 피해서 원래 목표까지 가는 걸 실제 로봇(`pinky1`)에서
여러 번 검증한 참고 구현입니다. 프로덕션에 그대로 붙이는 코드가 아니라
**"이 방식이면 실제로 된다"는 걸 증명한 프로토타입**입니다.

## 왜 이렇게 만들었는가

원래 시도했던 방법은 `nav2_costmap_2d::RangeSensorLayer`를 로컬+글로벌
코스트맵에 추가해서, Nav2 자체가 초음파 정보를 보고 알아서 경로를 재계획하게
하는 것이었습니다. 이 방식은 **팀 코드를 전혀 건드리지 않고** 자동으로 모든
주행 경로(QR 안내, 관제 수동 조작 등)에 적용된다는 장점이 있지만, 좁은
테스트 공간에서는 마킹된 셀 때문에 플래너가 갈 곳을 못 찾고 제자리에서
회전/후진만 반복하다 실패했습니다 (`nav2_params.yaml`에 그 설정은 남아있지만
이 PR에는 포함하지 않았습니다 — 실제 병원 지도처럼 넓은 공간에서 다시
검증이 필요합니다).

이 스크립트는 그 대안으로, Nav2의 표준 액션(`Spin`, `DriveOnHeading`,
`NavigateToPose`)만 이용해 코스트맵 재계획에 기대지 않고 직접 우회 동작을
수행합니다. **주의**: 이 스크립트가 직접 `NavigateToPose` 목표를 보내고
취소/재전송하는 구조라, `guide_manager`/`navigation_manager`가 보낸 목표에는
개입하지 못합니다. 실제 QR 안내 흐름과 합치려면 코스트맵 레이어 방식을
다시 살리거나, 이 로직을 해당 노드들 안으로 옮겨야 합니다.

## 동작 방식

1. `/us_sensor/range`가 임계값(기본 0.30m) 이하가 되면 목표를 취소하고 정지
2. **라이다 병행 확인**: 같은 방향에서 `/scan`도 뭔가 잡고 있으면(=일반 높이
   장애물) 개입하지 않고 그냥 둠 — Nav2가 이미 잘 처리할 대상이므로.
   초음파만 잡고 라이다는 못 볼 때만 "낮은 장애물"로 확정
3. 좌우로 10도씩 나눠 돌면서 매 스텝 초음파를 다시 읽어 더 열린 쪽을 찾음
   (한 번에 크게 돌고 판단하지 않음 — 로봇 몸통이 도중에 장애물을 스칠 수
   있어서)
4. 열린 방향을 찾으면 몸통이 완전히 빠져나오도록 여유각(기본 15도)을 더 돈 뒤
5. 8cm씩 나눠서 전진하며 매 스텝 재확인, 절대 위험거리(기본 0.10m) 아래로
   떨어지면 즉시 중단
6. 원래 각도로 복귀 후 원래 목표 재전송 (최대 `max_sidesteps`회 반복)
7. 한 번 고른 방향은 막히기 전까지 유지 (매번 새로 좌우 판단하면 진행한
   거리를 까먹음)

## 실행

패키지 빌드 불필요, ROS2 환경만 소싱하면 바로 실행됩니다.

```bash
python3 sidestep_node.py --ros-args \
  -p target_x:=1.72 -p target_y:=1.60 -p target_yaw_deg:=101.0 \
  -p trigger_distance:=0.30 \
  -p sidestep_forward_m:=0.35 \
  -p max_sidesteps:=4 \
  -p lidar_margin:=0.15
```

## 검증된 것 / 안 된 것

- 실제 로봇에서 여러 목적지(X-ray실, 진료실, 수납처, 입원병동) 좌표로
  낮은 장애물을 두고 반복 테스트하여 성공 사례를 다수 확보했습니다.
- 벽에서 너무 가까운(약 0.15m 미만) 좌표는 Nav2 플래너 자체의 한계로
  실패할 수 있습니다 (`config/waypoints/*.yaml` 헤더의 기존 문서 참고).
- 초음파는 정면 단일 빔이라 로봇 몸통 폭까지는 못 봅니다. 여유각을 더
  주는 정도로 완화했지만, 완전히 해결된 것은 아닙니다 — 여전히 스치는
  사례가 보고되었습니다.
- 좌우 판단과 우회 동작 모두 초음파에만 의존합니다. 라이다는 "낮은
  장애물인지 판별"에만 쓰이고, 우회 방향 결정에는 관여하지 않습니다
  (라이다는 애초에 그 장애물을 못 보므로).
