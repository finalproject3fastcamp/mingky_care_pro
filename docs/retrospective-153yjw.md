## 어떻게 일했나

저는 초보고, 이번 프로젝트는 처음부터 끝까지 바이브코딩이었습니다.
코드를 줄 단위로 검토할 실력이 안 되니 AI 와 대화로 만들고 결과로
확인하는 방식이었고, 매번이 신뢰의 도약이었습니다. 그래서 에러덩어리를
만든 적도 많습니다. 로봇 폴더에서 빌드를 돌려 잘 돌던 로봇을 세운 적도
있고, 리뷰 지적에 답을 달지 않아 PR 을 오래 묵힌 적도 있습니다.

대신 사고가 날 때마다 규칙을 하나씩 만들었습니다.

- **작업방 분리** — 실행 폴더는 항상 main, 작업은 별도 워크트리에서만
- **push 검문** — 전체 테스트(마지막엔 364개)를 통과해야 나가고, main
  직행은 기계가 막습니다
- **검증한 것만 보고** — 테스트를 일부러 깨뜨려 잡히는지 확인하고,
  오류·전환·통신 단절 같은 경우를 하네스로 돌려본 뒤에 리뷰를 요청

## 설계에서 지키려 한 것

새 통로를 뚫지 않고 이미 있는 길을 재사용했습니다. 경로이탈 복귀는
의료진 취소 토픽에 같은 요청을 넣는 것으로 구현해 guide_manager 를 한
줄도 고치지 않았고, OMX 비상정지는 기존 추론 서버를 가중치만 바꿔
재사용해 새 서버 코드가 없습니다. 실력이 부족한 만큼 팀이 만들어 둔
구조를 최대한 그대로 썼습니다.

## 마무리

늘 에러덩어리였지만, 한 것들이 적어도 모양이 나와서 뿌듯합니다.
로봇은 환자를 놓치면 20초를 세고 충전소로 가고, 그 시간이 관제 화면에서
줄어듭니다. 남은 리뷰 반영과 실기 검증은 발표 전까지 마무리하겠습니다.
