# 밍키케어프로 회고 — 정우


5주 동안 병원 안내 로봇이라는 하나의 시스템을 함께 만들 수 있어서
즐거웠습니다. 제가 맡았던 것과 배운 것을 정리해 공유합니다.

## 맡은 부분

| 영역 | 내용 | 결과 |
|---|---|---|
| 배터리 감시 | 저전압 판정 전환의 근거 실측, I2C 이중 리더 오염 발견 | #71 병합, #69·#79 정리 중 |
| 3D 병원 지도 | 라이노 실측 모형을 관제 화면에서 직접 렌더링, 로봇 위치·상태 표시 | #106 등 병합 |
| 경로이탈 | 환자를 놓치면 20초 대기 후 충전소 복귀 + 관제 표시(맥박·줌·카운트다운) | #136·#135 병합, #141 리뷰 중 |
| OMX 비상정지 | 포장 중 사람 감지 시 팔 토크 해제 (FC-14) | #143 리뷰 중 |

## 설계에서 지키려 한 것 — "있는 문으로 들어가기"

새 기능을 만들 때 새 통로를 뚫지 않고 팀이 이미 만든 길을 재사용하는
방향을 유지했습니다.

- 경로이탈 복귀는 의료진 취소 토픽에 같은 요청을 넣는 것으로 구현 —
  guide_manager 는 한 줄도 고치지 않았습니다
- OMX 비상정지는 인형 추종의 infer_server 를 가중치만 바꿔 재사용 —
  새 서버 코드 0줄
- 정지 경로도 러너가 원래 갖고 있던 finally 그대로

팀원들이 만들어 둔 구조가 튼튼해서 가능했던 방식이라고 생각합니다.

## 배운 것

**리뷰 소통의 타이밍.** 초반에 리뷰 지적을 코드로는 반영했는데 답글을
달지 않아 PR 이 오래 묵었습니다. "고쳤습니다" 한 줄이 코드만큼
중요하다는 걸 배웠습니다. 후반에는 검증 과정과 충돌 해결책까지 PR 댓글로
먼저 남기는 쪽으로 바꿨습니다.

**팀원 코드에 대한 예의.** 제 화면을 고치다가 다른 화면까지 손댔던 적이
있었고, 그 뒤로는 "내 담당 밖은 여쭙고 시작" 을 원칙으로 삼았습니다.
경로재설정(FC-12)처럼 담당이 겹쳐 보이는 카드는 먼저 확인하겠습니다.

**검증한 것만 보고하기.** AI 와 함께 작업하면서 "됐다" 와 "됐다고 한다"
의 차이를 여러 번 겪었습니다. 후반부터는 병합 전에 테스트를 일부러
깨뜨려 잡히는지 확인하고, 오류·전환·통신 단절 같은 경우를 하네스로
돌려본 뒤에만 리뷰를 요청했습니다.

## 감사

- 원민님 — 꼼꼼한 리뷰와 통합 브랜치에서 제 코드의 빈틈(오류 시 상태
  잔존, 중복 스트림)까지 다듬어 주신 것, 많이 배웠습니다
- 명일님 — 로봇 타입 분리 덕에 화면 작업이 안전해졌습니다
- 종수님·수정님 — 추론 서버 패턴을 잘 만들어 두신 덕에 비상정지를
  하루 만에 올릴 수 있었습니다
