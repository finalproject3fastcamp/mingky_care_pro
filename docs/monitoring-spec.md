# 관제 기능 스펙

Pinky + OMX 병원 서비스의 실시간 모니터링·관제 기능 정의.

## 1. 입력 인터페이스

### QR 인식

- **매체**: 환자 카드(QR) — 사원증 사이즈 프린트물
  - 모바일 대시보드 옵션 대신 프린트물 채택 (환자 접근성·간편함 우선)
- **인식 장치**: Pinky에 탑재된 IMX219 CSI 카메라
  - 핸드폰으로 서버 전송 방식 대신, 프로젝트 목적에 맞춰 Pinky 활용
- **QR 페이로드**: 환자 ID(또는 서명된 예약 토큰)
  - QR → DB 조회로 오늘 진료 일정 로드
  - 환자의 민감한 개인정보 노출 주의

### 구현

| 구성 요소 | 위치 |
| --- | --- |
| QR 인식 ROS2 노드 | [`mingky_ros/mingky_qr_reader/`](../mingky_ros/mingky_qr_reader/) |
| launch / config | [`mingky_ros/mingky_bringup/`](../mingky_ros/mingky_bringup/) (`qr_reader.launch.py`, `config/qr_reader.yaml`) |
| 백엔드 엔드포인트 `POST /qr/scan` | [`backend/app/routers/qr.py`](../backend/app/routers/qr.py) |
| 인쇄용 환자 카드 생성기 | [`mingky_ros/mingky_qr_reader/scripts/generate_cards.py`](../mingky_ros/mingky_qr_reader/scripts/generate_cards.py) |

## 2. 기술 스택 및 결정 배경

| 영역 | 선택 | 대안 | 선택 이유 |
| --- | --- | --- | --- |
| 프론트 | **React (Vite) + TypeScript** | Next.js, Vue | 팀 익숙도 높음, SSR 불필요 (사내망 SPA), Vite로 초기 세팅·HMR 빠름 |
| 백엔드 | **FastAPI (Python)** | Node/Express | ROS·머신러닝과 같은 Python 생태계, 자동 문서화(OpenAPI), 비동기 지원 |
| DB | **PostgreSQL** | — | 이미 채택 (`database/`에 세팅 완료) |
| QR → 서버 | **HTTP POST** | ROS 토픽 → 브릿지 | QR 스캔은 "요청-응답" 시나리오 (환자 확인 응답 즉시 필요), 구현·디버깅 단순 |
| 상태 갱신 | **Polling (3~5초)** | WebSocket, SSE | 사람 반응 속도면 초 단위로 충분, WebSocket은 MVP엔 오버엔지니어링 |
| QR 페이로드 | **patient_id 평문 (MVP)** | 서명 토큰 | 사내망 데모 우선, 나중에 서명 토큰으로 강화 예정 |

## 3. 대시보드 구성

### 3.1 의료진 대시보드 — 담당: 수진

**목적**: 환자·로봇의 현재 상태를 한눈에 파악

| 영역      | 표시 내용                                                    |
| --------- | ------------------------------------------------------------ |
| 환자 정보 | 이름, 나이, 오늘 진료 일정 리스트, 현재 단계                 |
| 진행률    | `접수 → X-ray → CT → 진료 → 물리치료 → 약국` 중 현재 위치    |
| 로봇 상태 | 상태 라벨(대기/이동중/도착/검사중/완료), 배터리, 현재 목적지 |
| 로봇 시야 | Pinky IMX219 카메라 라이브 프리뷰                            |
| 알림      | QR 인식 실패, 도착, 검사 완료, 통신 두절                     |

**우선 담당 작업**

- 프론트 초기 세팅
- QR 코드 인식 파이프라인 (IMX219 → 디코딩 → 서버 전송)

### 3.2 엔지니어 대시보드 — 담당: 명일

**목적**: 디버깅과 시스템 상태 진단

| 영역             | 표시 내용                                         |
| ---------------- | ------------------------------------------------- |
| ROS 상태         | 노드/토픽 살아있는지, 주기 이상 여부              |
| 주행 로그        | Nav2 경로계획, 로컬라이제이션, 장애물 회피 이벤트 |
| OMX 로그         | 팔 조작 이벤트, Pick & Place 성공/실패            |
| 이벤트 타임라인  | 시간대·레벨·노드별 필터                           |
| 원시 로그 스트림 | tail 형태의 실시간 로그                           |

## 4. 로봇/환자 상태 정의 (State Machine)

```
대기 → QR 인식 → 환자 확인 → 안내중 → 도착 → 검사중 → 완료
                                            ↓
                                       다음 목적지 / 종료
```

**예외 상태**

- `QR 인식 실패`
- `경로 이탈`
- `통신 두절`
- `배터리 부족`
- `일시정지` (수동 개입)

상태 전이 조건과 타임아웃은 구현 단계에서 별도 정의.

## 5. 데이터 흐름

```
[환자 카드 QR]
      ↓ IMX219
   [Pinky QR 노드]
      ↓ HTTP POST /qr/scan
   [FastAPI 서버]
      ├→ PostgreSQL (영속)
      └→ (프론트가 3~5초 주기로 polling)
              ↓
    ┌─────────┴─────────┐
[의료진 대시보드]  [엔지니어 대시보드]
     (React)
```

- 카메라 라이브 스트림은 별도 채널로 분리 예정 (프로토콜 미결정)

## 6. 미결정 항목
