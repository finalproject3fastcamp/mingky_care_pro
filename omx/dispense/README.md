# 조제 킷 — 트레이의 알약을 약통에 담는다

**이번 업데이트**: SmolVLA 로 실기 성공한 첫 판(`smolvla10`)이 추가됐다.
자세한 내용은 `smolvla_v10_snippet.md` 를 먼저 읽는다.

## 왜 코드만 있고 체크포인트는 없나

정책 가중치는 5GB~9GB 라 저장소에 못 넣는다. 정본은 `~/omx_pill_project` 에 두고,
백엔드는 `OMX_PILL_ROOT` 환경 변수로 그 경로를 찾는다 (기본 `~/omx_pill_project`).

여기 있는 것은 **읽기용 사본**이다. 고칠 때는 `~/omx_pill_project` 를 고치고
다시 복사한다 — 이 폴더를 직접 고치면 실기에 반영되지 않는다.

## 파일

| 파일 | 하는 일 |
| --- | --- |
| `run_policy.py` | 정책을 실행해 로봇을 움직인다. 연속 조제(`--sequence`)도 여기서 처리 |
| `run.sh` | il venv 를 source 하고 `run_policy.py` 를 부른다 |
| `pharmacy.py` | 트레이의 알약을 색별로 센다 (HSV) |
| `dispense_onehot.sh` | 수동 실행용 진입점. 정책 이름 → 체크포인트·데이터셋 대응표 |
| `make_xy_labels.py` | 목표 알약의 화면 좌표를 찾는다. 좌표 조건화 정책이 매 프레임 쓴다 |
| `make_onehot.py` | 태스크 문자열에서 색을 뽑는다 |
| `area.json` | 트레이 영역 (이 밖의 검출은 버린다) |
| `home_pose.json` | 홈 자세 |
| `grasp_offset.json` | 색별 파지 보정값 |
| `smolvla_v10_snippet.md` | **SmolVLA v10 을 어떻게 연결하는지** — 새로 추가 |

## 쓰는 정책

정본은 `omx/web/policies.json`. 추천은 좌표 조건화(`act_xy_224`)와
**새로 추가된 `smolvla10`**.

| 정책 | 목표 지정 | 실측 |
| --- | --- | --- |
| `xy` (`act_xy_224`) | 화면 좌표 | **실기 3색 연속 성공**. 색 판별은 HSV 검출기가 한다 |
| `film224` (`act_film_224`) | 원-핫 벡터 + FiLM | **실기 3색 연속 성공**. 검출기 없이 정책이 색을 구분한다 |
| `act_*_224` | 색마다 다른 모델 | 색별로는 되지만 모델이 3개 필요 |
| **`smolvla10`** | **좌표를 `observation.state` 로** | **실기 성공. SmolVLA 로는 처음** — huggingface.co/kimy0420/smolvla_v10 |
| `smolvla_v3~v9` | 언어 | 전부 실패 — 색을 무시한다 |

**오프라인 지표로 실기를 예측하지 못한다.** film224 는 자기색 대비 1.25배로
실기에 성공했고, smolvla_v8 은 2.02배인데 실기에서 못 썼다(떨림·헤맴,
그리퍼 0회). 실기는 반드시 직접 돌려서 확인한다.

`xy` · `film224` · `smolvla10` 는 색을 아는 주체가 다르다. `xy` 와 `smolvla10`
은 HSV 검출기가 색을 찾아 좌표를 주고 정책은 "거기로 가서 집기" 만 한다.
`film224` 는 원-핫만 받고 **정책이 화면에서 그 색을 찾는다** — 검출기가
필요 없다.

## 주의 — `--hold-home` 과 연속 조제

`--hold-home`(기본 켬)은 트레이에 목표 색이 없으면 홈에서 붙잡는 안전장치다.
연속 조제에서는 색이 바뀔 때 `TASK_COLOR` 도 같이 바꿔야 한다. 안 그러면
앞 색을 담아 없앤 뒤 "목표 색이 없다" 며 영영 안 움직인다 (2026-08-20 에
웹 조제에서 실제로 걸렸다 — 초록을 담은 뒤 노랑으로 못 갔다).
