# 안 될 때 보는 문서

증상 → 원인 → 조치. **저희가 실제로 겪은 것만** 적었습니다.

---

## 로봇을 못 찾는다

| 증상 | 확인 | 조치 |
|---|---|---|
| `/dev/ttyACM*` 가 아예 없다 | USB·전원 어댑터 | 로봇은 USB만 꽂아선 안 켜집니다. 전원 어댑터 확인 |
| 장치는 보이는데 권한 오류 | `groups \| grep dialout` | 없으면 **로그아웃 → 로그인** (01_install.sh 가 그룹에 추가해뒀습니다) |
| `/dev/omx_follower` 가 없다 | `ls -l /dev/omx_*` | `bash 02_find_ports.sh` 다시. USB 를 뺐다 꽂아보세요 |
| 포트를 못 연다 | 다른 프로그램 | 녹화·평가 창이 떠 있으면 먼저 끄세요. 시리얼 포트는 한 번에 한 프로그램만 씁니다 |

## 모터가 죽은 것 같다

**케이블을 먼저 의심하세요.** 저희는 특정 모터(12번)가 과부하로 멈추는 걸 소프트웨어
문제로 보고 drive_mode·homing offset·range 를 다 건드렸다가 전부 원복했습니다.
**진짜 원인은 관절을 넘어가는 케이블 장력**이었습니다.

증상들:
- 특정 자세에서만 과부하로 멈춘다 → 그 자세에서 케이블이 팽팽해지는지 보세요
- `device disconnected` 가 뜬다 → 케이블이 당겨져 USB 보드가 커넥터에서 빠진 겁니다
- 팔이 가끔 "툭" 하고 튄다 → 통신 패킷이 씹히는 겁니다. 역시 케이블

## 카메라

| 증상 | 원인 | 조치 |
|---|---|---|
| 카메라를 못 찾는다 | `/dev/videoN` 번호가 바뀜 | 이 킷은 `/dev/v4l/by-id/` 를 씁니다. `ls /dev/v4l/by-id/` 로 확인 |
| 방금 전까지 되던 카메라가 "열기 실패" | `udevadm trigger` 가 카메라까지 재열거함 | `02_find_ports.sh` 직후에 흔합니다. **몇 초 기다렸다 다시** 실행하세요 |
| `--view` 가 GTK 오류로 죽는다 | `opencv-python-headless` (lerobot 요구사항) | 자동으로 `ffplay` 로 띄웁니다. GUI 버전 opencv 를 설치하면 lerobot 과 충돌하므로 **바꾸지 마세요** |
| 초점을 어디서 멈춰야 할지 모르겠다 | — | `bash 03_focus.sh top` 으로 선명도를 실시간으로 보면서 돌리세요 |
| 화면이 전부 검정 | USB 접촉 불량 | 다시 꽂기 |
| 컬러 줄무늬 노이즈 | 케이블 불량·연장선·허브 | **짧은 케이블로 노트북에 직접** 꽂으면 해결됩니다 |
| 녹화 중 카메라가 자꾸 끊김 | USB 자동절전 | 아래 명령 |
| fps 가 30이 안 나온다 | 카메라와 모터가 같은 허브 | USB 포트를 나눠 꽂으세요 |
| 해상도 설정이 안 먹는다 | FFMPEG 백엔드 | `backend: V4L2` + `fourcc: MJPG` (스크립트에 이미 들어 있음) |

USB 자동절전 끄기 — 저희는 이것 때문에 카메라가 **하루에 36번** 끊겼습니다
(`Failed to resubmit video URB (-19)`):

```bash
lsusb -t                                              # 카메라가 붙은 포트 번호 확인 (예: 1-1.3)
echo on | sudo tee /sys/bus/usb/devices/1-1.3/power/control
```

## 녹화 중

| 증상 | 원인 | 조치 |
|---|---|---|
| `→` `←` 키가 안 먹는다 | 다른 창에 포커스가 있음 | 패치는 터미널 stdin 을 읽습니다. **명령을 실행한 터미널 창을 클릭**하고 누르세요 (rerun 창 아님) |
| 키가 하나도 안 먹는다 | 패치 미적용 + Wayland | pynput 전역 후킹은 Wayland 에서 아무 이벤트도 못 받습니다. `01_install.sh` 로 패치를 넣으세요 |
| 종료한 뒤 터미널이 이상하다 | cbreak 모드가 안 풀림 | `reset` 을 치면 돌아옵니다 (정상 종료 시엔 자동 복구됩니다) |
| 에피소드가 0프레임으로 저장됨 | 저장·인코딩 중에 `→` 를 누름 | 패치를 넣으면 해결됩니다 (01_install.sh) |
| 실행이 죽어서 데이터가 걱정됨 | — | **저장된 건 안 망가집니다.** `bash 05_record.sh 20 resume` 로 이어 찍으세요 |
| 몇 개나 찍혔는지 모르겠다 | — | `ls ~/.cache/huggingface/lerobot/<REPO>/videos/chunk-000/observation.images.top \| wc -l` |

## 학습

| 증상 | 조치 |
|---|---|
| CUDA out of memory | `BATCH_SIZE=4 bash 06_train.sh` 로 줄이세요 |
| 너무 느리다 | 정상입니다. 40000 스텝에 3~8시간. 노트북 절전이 안 걸리게 설정하세요 |
| 중간에 끊겼다 | 8000 스텝마다 체크포인트가 저장됩니다. `~/train/<이름>/checkpoints/` 확인 |

## 학습은 됐는데 로봇이 이상하게 움직인다

**여기서 절대 하지 말아야 할 것: 곧바로 데이터를 더 모아서 재학습하기.**
저희가 3일을 그렇게 썼고, 재학습으로 확인하려던 가설이 두 개 다 틀렸습니다. 8시간을 버릴 뻔했습니다.

원인을 좁히는 순서:

1. **카메라 화각이 녹화 때와 같은가** — 제일 흔한 원인입니다. 녹화 영상 한 장과
   지금 화면을 나란히 놓고 비교하세요. 몇 픽셀 차이도 영향이 있습니다
2. **초점이 풀리지 않았나** — `03_check_cameras.sh` 의 선명도 값을 녹화 때와 비교
3. **조명이 달라지지 않았나** — 커튼, 형광등, 시간대
4. **카메라 키 이름이 맞나** — 학습할 때 `top`/`wrist` 였다면 실행할 때도 같아야 합니다
5. 여기까지 다 같은데도 이상하면 → 그때 데이터 문제를 의심하세요

증상별로는:

- **엉뚱한 방향으로 간다** → 1~3번
- **근처까지 가는데 못 잡는다** → 시연할 때 파지 자세가 매번 달랐을 가능성. 일관되게 다시 시연
- **아예 안 움직인다** → 체크포인트 경로, 카메라 키 이름
- **물건이 없는데도 계속 헤맨다** → 회복 시연(실패했다 다시 잡기)을 너무 많이 넣으면
  "없으면 멈춘다"를 못 배웁니다. **회복 능력과 정지 조건은 맞바꿈 관계입니다**
- **비슷하게 생긴 걸 구분 못 한다** → 증강(`image_transforms.enable`)이 켜져 있는지 확인.
  이걸 끄면 장면을 통째로 외워서 무엇을 봐야 하는지를 안 배웁니다

## 제일 중요한 원칙 세 가지

1. **되는 상태를 먼저 저장한다.** 뭔가 고치기 전에 백업/커밋
2. **재학습은 진단이 아니다.** 원인을 지목한 뒤에 재학습합니다
3. **한 번에 하나만 바꾼다.** 두 개를 같이 바꾸면 뭐가 효과였는지 영영 모릅니다
