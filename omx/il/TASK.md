# 작업 정의와 진행 기록

학습을 시작하기 **전에** 정하고, 진행하면서 채워 넣는 문서다.
왜 미리 정하나 — 평가 결과를 보고 나서 기준을 정하면 "이 정도면 된 것 같다"가 되어버려서
무엇을 고쳐야 하는지 영영 못 정한다.

---

## 1. 작업

| | |
| --- | --- |
| 작업 | 알약이 담긴 약통을 집어 봉투에 넣는다 |
| `TASK` | `put the pill bottle in the envelope` |
| `REPO` | `mingky/pill_bottle_v1` |
| 목표 개수 | **하나** (약통 1종, 봉투 1개, 항상 같은 곳에 넣는다) |
| `film_conditioning` | **끔.** 목표가 하나라 필요 없다 |

`TASK` 문자열은 녹화(05)와 평가(07)에서 **글자 하나까지 같아야 한다.** 데이터에 그대로
들어가고 정책을 부를 때도 같은 문자열을 쓰기 때문이다. 다듬고 싶어도 두어야 한다.

목표를 여러 개로 늘릴 때(여러 약통 중 고르기, 트레이 칸 지정)는
`REPO` 를 새 이름으로 바꾸고 `film_conditioning=true` 를 켠다. 근거는 [README](README.md) 참고.

### 무엇을 성공으로 치는가

- **성공** — 약통을 집어 봉투 안에 넣고 그리퍼를 놓는다. 약통이 봉투 밖으로 나와 있지 않다
- **실패** — 아래 중 하나라도 해당하면 실패로 센다
  - 못 잡음 (그리퍼가 헛돌거나 스쳐 지나감)
  - 잡았지만 도중에 떨어뜨림
  - 약통을 쓰러뜨림 (알약이 쏟아지면 그 회차는 실패)
  - 봉투 밖에 놓음, 봉투 위에 걸침
  - 시간 상한(60초)까지 헤맴
- **판정 보류** — 사람이 개입(스페이스바)한 회차는 성공·실패 어느 쪽에도 세지 않는다

### 규모

| | |
| --- | --- |
| 데이터 | 30~50 에피소드 (부족하면 늘리되, 늘리기 전에 원인부터 좁힌다) |
| 학습 | 40000 스텝 / `batch_size=16` (RTX 5080 16GB 기준 자동 선택) |

결과가 기대에 못 미쳐도 **바로 데이터를 더 모으지 않는다.**
[TROUBLESHOOTING.md](TROUBLESHOOTING.md) 의 진단 순서를 먼저 따른다.

값을 적어두지 않으면 비교할 대상이 없어진다.

| wrist 카메라 (by-id) | `usb-Innomaker_Innomaker-U20CAM-720P_SN0001-video-index0` | 확정 |

선명도는 **초점 조정 전 10.3 → 조정 후 840 전후**다. 100 아래로 떨어지면 초점이 풀린 것이다.
밝기가 한 자릿수면 초점이 아니라 **USB 연결**을 의심한다 (아래).

### USB 배치 — 카메라와 모터를 같은 허브에 두지 않는다

2026-08-11 에 top 카메라가 완전한 검은 화면(모든 픽셀 0)이 되는 일이 있었다.
노출을 25배로 올려도 0이었고, **USB 를 다시 꽂으니 바로 복구**됐다.

원인은 배치였다 — top 카메라가 로봇 팔 2대와 **같은 4포트 허브**에 물려 있었다
(장치 번호가 049 → 055 로 여섯 번 재열거된 흔적이 남아 있었다).
정상이던 wrist 는 노트북에 직접 꽂혀 있었다.

- 카메라는 **노트북 포트에 직접**, 짧은 케이블로. 카메라 두 대도 서로 다른 포트에
- 로봇 팔은 허브에 둬도 된다 (12Mbps 라 대역폭을 거의 안 쓴다)
- 배치를 확정한 뒤 **자동절전을 끈다** (재부팅하면 풀리므로 다시 해야 한다):
  ```bash
  lsusb -t                                                   # 포트 번호 확인
  echo on | sudo tee /sys/bus/usb/devices/<포트>/power/control
  ```

> 카메라 by-id 경로는 노트북마다 다르다. `cams.env` 는 저장소에 올리지 않으므로
> 다른 노트북에서 쓸 때는 `03_check_cameras.sh --view` 로 각자 만든다.

### 약통 배치 격자

같은 자리에 두면 모델이 위치를 외운다. 눈대중으로 찍었다가 세 자리에만 몰려서
전부 다시 찍은 적이 있다. **미리 자리를 그려두고 순서대로 소진한다.**

작업대에 격자를 그리고 칸마다 몇 번 찍었는지 세면서 진행한다.
위치뿐 아니라 **약통을 세운 각도**도 같이 바꾼다.

## 3. 결과 (2026-08-12)

- **데이터** 29 에피소드 / 20,061 프레임. 길이 중앙값 22.8초, 표준편차 2.7초.
  30개를 찍고 시간 상한에 걸린 1개(15번)를 `lerobot-edit-dataset` 으로 삭제했다.
- **학습** ACT, 40,000 스텝 = 31.9 에폭, batch 16, 5시간 24분 (RTX 5080 16GB).
  loss 6.082 → 0.052, grad norm 120 → 4.4. 발산·정체 없이 단조 감소.
- **평가** 9회차까지 기록 후 중단. **시도한 것은 전부 성공**했다.
  한 번 옮기는 데 걸린 시간은 **20초 내외로 사람 시연(22.8초)과 같은 수준**이다.
  회차 평균이 47.2초로 나온 것은 한 회차 안에서 두 번 옮긴 경우가 있어서다.

**집계가 안 된 이유.** 한 회차 안에서 여러 번 시도하기도 해서 "10회 중 몇 회 성공"을
셀 수 없었다. 재측정하지 않는다 — "시도한 것은 전부 성공"이 결론이다.

**아직 확인하지 않은 것**
- 약통을 격자 **가장자리**에 놨을 때도 되는지 (위치 일반화)
- 학습 때 안 쓴 위치·각도에서도 되는지
- wrist 카메라에 그리퍼가 잡히는지 (세팅 단계에서 확인을 건너뛰었다)
