# OMX 모방학습 시작 킷

로봇과 카메라를 노트북에 연결한 상태에서 **번호 순서대로 하나씩 실행하면 됩니다.**

작업: 알약통을 봉투에 넣기 (`_common.sh` 의 `TASK` 를 고치면 다른 작업으로 바꿀 수 있습니다)

---

## 순서

| 단계 | 명령 | 언제 | 걸리는 시간 |
|---|---|---|---|
| 1 | `bash 01_install.sh` | **한 번만** | 20~40분 |
| 2 | `bash 02_find_ports.sh` | 한 번만 (로봇 바꾸면 다시) | 1분 |
| 3 | `bash 03_check_cameras.sh --view` | 한 번만 (카메라 바꾸면 다시) | 5분 |
| 4 | `bash 04_teleop.sh` | 여기까지 되면 세팅 끝 | 5분 |
| 5 | `bash 05_record.sh 20` | 데이터 모을 때마다 | 개당 1~2분 |
| 6 | `bash 06_train.sh` | 데이터 다 모은 뒤 | 3~8시간 |
| 7 | `bash 07_run.sh` | 학습 끝난 뒤 | — |

> **1단계 뒤에 로그아웃 → 로그인을 꼭 하세요.** 시리얼 포트 권한(dialout 그룹)이
> 다시 로그인해야 적용됩니다. 이걸 안 해서 "로봇을 못 찾는다"가 제일 흔합니다.

---

## 각 단계에서 무슨 일이 일어나나

### 1. `01_install.sh` — 환경 설치
파이썬 가상환경(`~/venv/il`)을 만들고 LeRobot **v0.4.4** 를 설치합니다.
버전을 고정한 이유는 최신 버전(0.6.x)이 명령어 체계가 달라서 이 킷의 스크립트가 안 맞기 때문입니다.

같이 들어 있는 `lerobot_local_v0.4.4.patch` 도 자동 적용됩니다 — 카메라 재연결·저장 순서·첫
에피소드 대기·Wayland 키 입력·DAgger 개입(7단계 참고)·ACT FiLM 조건화까지 6개 수정입니다.
어떤 사고를 막는 패치인지 자세한 배경은
[../../docs/omx-imitation-learning.md §4](../../docs/omx-imitation-learning.md#4-lerobot-로컬-패치) 에서 봅니다.

> 패치가 깨끗이 적용되지 않으면 `01_install.sh` 는 **멈춥니다.** 패치 없이 녹화하면
> 데이터를 잃고 나서야 알게 되기 때문입니다. 안내에 따라 병합한 뒤 다시 실행하세요.

### 2. `02_find_ports.sh` — 포트 이름 고정
`/dev/ttyACM0`, `/dev/ttyACM1` 번호는 **꽂는 순서와 재부팅마다 바뀝니다.**
어제 팔로워였던 게 오늘 리더가 됩니다. 그래서 보드 시리얼 번호로 이름을 고정합니다:

- `/dev/omx_follower` (실제로 움직이는 팔)
- `/dev/omx_leader` (손으로 잡고 조종하는 팔)

팔로워/리더 구분은 USB 장치 이름이 아니라 **모터 ID** 로 합니다 (팔로워 11~16, 리더 1~6).
장치 이름으로는 절대 알 수 없습니다.

### 3. `03_check_cameras.sh --view` — 카메라 정하기
연결된 카메라를 찾아 화면에 띄웁니다. 보고서 어느 게 `top`(위에서 내려보는 고정 카메라),
어느 게 `wrist`(팔에 달린 카메라)인지 번호로 고르면 `cams.env` 에 저장됩니다.

**이름만 보고 추정하지 마세요.** 저희는 장치 이름으로 판단했다가 top/wrist 를 반대로
잡아둔 걸 이틀 뒤에 화면을 보고 알았습니다.

이 단계에서 밝기·선명도도 같이 재줍니다:
- 밝기가 0에 가까움 → USB 가 반쯤 빠진 것
- 선명도가 너무 낮음(100 미만) → 렌즈 초점이 풀린 것

초점을 맞출 때는 **선명도를 실시간으로 보면서** 렌즈 링을 돌리세요:

```bash
bash 03_focus.sh top      # 또는 wrist, 번호, /dev/... 경로
```

숫자가 제일 커지는 지점이 초점입니다. 최고점을 지나면 막대가 줄어들어 바로 보입니다.
**맞춘 뒤 렌즈 링을 테이프로 고정하세요** (초점이 풀린 채로 평가를 두 번 돌려 결과를
버린 적이 있습니다). 그리고 그 숫자를 [TASK.md](TASK.md) 에 적어두세요.

> lerobot 이 `opencv-python-headless` 를 요구해서 **`cv2.imshow` 를 못 쓰는 환경이 많습니다.**
> 그런 경우 `--view` 는 `ffplay` 로 창을 띄우고, `03_focus.sh` 는 숫자만 출력합니다.
> 둘 다 알아서 판단하므로 따로 할 일은 없습니다.

### 4. `04_teleop.sh` — 로봇 움직이기
리더를 손으로 움직이면 팔로워가 따라옵니다. **여기까지 되면 하드웨어 세팅은 끝입니다.**

`bash 04_teleop.sh --cam` 으로 카메라 화면까지 같이 띄워서, 작업 장면이 두 카메라에
제대로 들어오는지 확인하세요. 특히 **그리퍼가 물건을 잡는 순간이 화면에 보여야** 합니다.

### 5. `05_record.sh 20` — 데이터 녹화
리더로 직접 시연하면 그게 학습 데이터가 됩니다.

- `→` = "내 할 일 끝났음" (시연 끝나고 한 번, 물건 다시 놓고 한 번)
- `←` = 지금 것 버리고 다시
- 숫자는 **이번에 추가로 찍을 개수**입니다. 이어 찍을 땐 `bash 05_record.sh 20 resume`

> **키는 명령을 실행한 터미널 창에 눌러야 합니다.** 패치가 stdin 을 직접 읽기 때문에
> rerun 시각화 창이나 다른 창에 포커스가 있으면 키가 안 먹습니다. 반대로 다른 창에서
> 잘못 누른 키가 녹화를 망치는 일도 없어졌습니다.

**매번 물건 위치와 각도를 바꾸세요.** 같은 자리에 두면 모델이 위치를 외워버립니다.
저희는 30개를 눈대중으로 찍었다가 딱 3자리에만 몰려 있어서 전부 다시 찍었습니다.

몇 개가 필요한지: 저희는 색깔 하나당 30개 전후로 됐습니다. 처음엔 **30~50개**로
학습해보고, 되는지 보고 늘리는 게 낫습니다.

### 6. `06_train.sh` — 학습
GPU 메모리를 보고 배치 크기를 알아서 정합니다. 3~8시간 걸립니다.

**색·밝기 증강(`image_transforms.enable=true`)이 켜져 있습니다. 끄지 마세요.**
이게 이 프로젝트에서 제일 크게 데인 부분입니다 — 증강을 끄면 각 장면이 딱 한 번씩만
나오니까 "이 화면 = 이 궤적"으로 통째로 외워버리고, 정작 무엇을 보고 판단해야 하는지를
배우지 않습니다. 증강은 데이터를 늘리는 게 아니라 **외우는 지름길을 막는 장치**입니다.

### 7. `07_run.sh` — 실기에서 돌려보기
학습된 정책이 혼자 움직입니다. **처음엔 전원 스위치 근처에 손을 두고** 시작하세요.

리더 팔을 같이 꽂아 두면 **스페이스바로 개입**할 수 있습니다 (DAgger). 켜면 리더가 팔로워
자세로 자동 정렬되니 **정렬되는 1.5초 동안 리더에서 손을 떼세요.** 그 뒤 리더로 직접 교정하면
그 동작이 데이터로 남고, 다시 스페이스바를 누르면 정책이 이어받습니다. 개입한 시간은
에피소드 시간 상한에서 빠지므로 천천히 가르쳐도 됩니다.
정책이 자꾸 틀리는 구간만 골라 모을 수 있어서, 처음부터 다시 찍는 것보다 효율적입니다.

카메라 위치가 녹화할 때와 같아야 합니다. 저희는 화각이 6픽셀 밀린 걸 모르고 평가하다
하루를 날렸습니다. 카메라는 테이프로 고정하세요.

## 설정 바꾸기

`_common.sh` 맨 아래 두 줄만 고치면 됩니다:

```bash
REPO=mingky/pill_bottle_v1                    # 데이터셋 이름
TASK="put the pill bottle in the envelope"    # 작업 설명
```

작업을 바꾸면 **데이터셋 이름도 반드시 바꾸세요.** 다른 작업 데이터가 한 데이터셋에
섞이면 되돌릴 수 없습니다.

지금 하는 작업의 정의·성공 기준·세팅 값·진행 기록은 [TASK.md](TASK.md) 에 있습니다.
**녹화를 시작하기 전에 거기부터 채우세요.** 평가 결과를 보고 나서 기준을 정하면
"이 정도면 된 것 같다"가 되어버려서 무엇을 고쳐야 할지 못 정합니다.

## 안 될 때

`TROUBLESHOOTING.md` 를 보세요. 저희가 실제로 겪은 것만 적어놨습니다.

한 가지만 미리 말하면 — **잘 안 될 때 데이터를 더 모아서 재학습하지 마세요.**
저희가 3일을 그렇게 날렸고, 재학습으로 검증하려던 가설이 두 개 다 틀렸습니다.
원인을 먼저 좁히고, 지목한 뒤에 재학습하세요.
